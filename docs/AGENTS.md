# 文档规则

撰写、改写或审阅本目录的 README、架构说明、功能说明、操作指南、设计计划或验证报告时，使用 [write-torchtitan-npu-docs](../.agents/skills/write-torchtitan-npu-docs/SKILL.md)。本文件规定文档归属和边界；skill 负责事实核对、中文技术表达、命令校验与交付检查。

## 文档归属

每个事实只在一个文档中完整解释，其他位置链接到它。文档树位置决定允许的细节，子文档拥有的实现细节不要复制到上层。

| 位置 | 职责 |
| --- | --- |
| `architecture.md` | 正式目标架构：目标布局、目录职责、导入/启用关系和验证边界；迁移阶段同步更新 |
| `developer_guides/` | 开发者使用的配置、lint、测试、checkpoint、指标与调试规则 |
| `feature_guides/` | 某项模型、并行、算子或优化能力的行为、启用方式、限制和验证 |
| `user-guides/` | 安装、快速开始和面向使用者的操作说明 |
| `community/` | 治理、贡献和版本等社区规则 |
| `.agents/notes/` | 迁移步骤、替代方案、风险、决策取舍和当前阶段状态；不替代目标架构说明 |

教程应按完成目标所需的前提顺序组织；参考文档定义稳定的查询范围和当前行为，不按教学步骤叙述。文档类型不扩大其负责范围。

## 写作规则

- `architecture.md` 可以规定目标正式结构；功能、开发者和用户文档只描述当前已实现事实，不将 PR、提交、迁移进度或未来目录写成当前行为。设计背景和阶段状态链接到 Agent Note。
- 首先说明读者需要的启用方式、适用条件和限制，再展开内部实现。能力受硬件、runtime、dtype、shape、layout、并行方式或激活模块影响时，明确这些边界。
- 中文优先；路径、命令、配置键、模块名、环境变量和其他机器可读标识符保持原样。命令必须有源码、配置、脚本或测试依据。
- 不宣称未经测量的性能或数值结论；区分已实现、已验证、有限支持、未验证和计划中。
- 不复制完整源码、文件清单、测试清单或另一个文档已拥有的细节。关系复杂时才使用表格、流程图或目录树。
- 文档变更如影响目标架构、功能启用、支持范围或命令，同步更新拥有该事实的当前态文档；非局部架构决定同时更新或新增 Agent Note。

## 验证与交付

按 skill 的“验证交付”流程核对链接、路径、配置、注册名、命令、支持范围和验证状态。运行成本可控的相关检查；不为文档校对无理由触发昂贵 NPU 训练，也不把未执行或替代命令写成已通过。
